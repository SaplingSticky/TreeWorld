# 我和 AI 共用一块无限画布：一个 vibe coding 项目的从 0 到 1

> 关键词：AI Agent · 无限画布 · vibe coding · 产品设计 · Tauri

## 开头：聊天窗口是降维通道

我们和 AI 对话的方式，十年没变过：一个窄窄的聊天框。

你说一句话，它回一段文字。文字里提到的"一个表格"、"一张图"、"三个要点"，全都挤在一段 Markdown 里。对话一滚，前面的内容就沉底了。

可思考不是线性的。想法会分叉、会长叶子、会被推倒重来。聊天窗口把这种立体结构压成了二维文本流——**对话是临时的，但想法需要一块能留下来的地方。**

所以我做了 TreeWorld：一块无限画布，你和 AI 都在上面操作。AI 的产出不是一段文字，而是画布上真实存在的东西：文档块、便签、图片、表格、一个装着一整套成果的集合框。

## 它跟现有产品有什么不同

| 产品 | 谁在操作画布 | 画布是谁的 |
|------|-------------|-----------|
| Notion | 人写，AI 补全 | 人的 |
| Miro | 人画，AI 建议 | 人的 |
| Claude Desktop | AI 写，人看 | AI 的 |
| **TreeWorld** | **人和 AI 都能操作** | **共享的** |

关键在于：AI 不是"助手"，是**共同编辑者**。它可以移动、修改、删除、组织画布上的内容——除了你锁定的那些。锁定机制是核心设计：人可以锁住任何块，被锁的块 AI 碰不了；AI 想改的时候会弹一张便签告诉你"这块锁了，先解锁"。

## 三个让 AI 真正"上桌"的设计决策

### 1. 对话是浮动的，不是界面

没有常驻聊天框。按 `/` 弹出一个气泡输入框，说完就消失。界面永远是画布，对话只是手段。

### 2. Agent 输出即画布内容（Canvas Command Protocol）

AI 和画布之间跑一个 JSON 指令协议：`canvas.create / update / move / resize / lock / delete / group / batch / query`。

做任务时 AI 先创建一个集合框，再往里面填内容——它做完任务，画布上多出来的不是一段话，而是一个结构化的成果。

### 3. 多轮执行循环：AI 会先查再动手

画布上下文有长度限制（视口内块 + 摘要，80 字符预览）。当 AI 需要操作一个内容被截断的长块时，它发 `canvas.query` 拿完整内容，系统回喂给它，它继续执行——最多 3 轮。

效果：你让它"把那份调研的第二点展开"，它不会凭 80 个字符的摘要瞎猜，而是先查到全文再改。

## 技术栈与两个关键实现

React 19 + TypeScript + Zustand + Vite，桌面壳是 Tauri 2（Rust + 系统 WebView）。数据本地存储，支持 Claude / OpenAI / Ollama 三种后端，可联网搜索（Tavily）。

**视口感知上下文**：每次对话只把当前视口内的块摘要推给 AI（含集合框，封顶 30 块 / 4000 字符），AI 需要更多时主动 query。这解决了无限画布最本质的问题——不能把整个画布塞进 prompt。

**放置避让**：AI 生成的内容自动排入视口附近的空地，检测与已有块的碰撞并整体下移，绝不压住你已有的东西。

## 踩过的坑（vibe coding 的真相）

1. **Prompt 撒谎**：早期 prompt 告诉模型"放在 x=100, y=100"，实际引擎会重排所有块。模型照着指令给坐标，全被覆盖。后来改成"坐标是提示，引擎自动布局"——prompt 必须说真话，否则模型永远学不会正确行为。
2. **协议定义了一半**：types 里定义了 `canvas.query`，prompt 里也教了，但执行引擎根本没有这个分支——模型发出的查询被静默丢弃。这类"半实现"是 vibe coding 最容易埋的雷，最后靠全量代码审查才挖出来。
3. **换壳**：v1.0 用 Electron，安装包 100MB+。v1.1 换 Tauri 2，deb 包 3.5MB，Windows 安装包 2.2MB。前端零改动——因为从一开始就坚持"前端是纯 Web 应用，壳只管窗口"，这个决定让换壳成本趋近于零。
4. **没有测试就是裸奔**：为这个项目补了 50 个单测（指令引擎、解析器、碰撞避让），CI 全绿之后才敢发 release。AI 写代码快，但 AI 写的代码更需要测试兜底。

## 收获

vibe coding 不是"AI 写代码我躺着"。真正值钱的是**想清楚产品再动手**——这份项目的设计文档（定位、机制、协议、安全沙箱）写了两千字，开发反而是顺着文档走。AI 负责把想法变成代码，你负责把想法想清楚。两边各干各擅长的。
