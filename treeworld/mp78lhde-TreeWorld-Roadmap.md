# TreeWorld Roadmap

> 基于 MVP 三阶段完成后的状态制定。
> 优先级从高到低排列，同一阶段内的任务可以并行，但建议按顺序完成。

---

## 当前状态（基线）

- 无限画布：pan / zoom / drag ✅
- 块类型：MD、便签、气泡、图片、HTML、集合框 ✅
- Agent 接入：Anthropic / OpenAI-compatible ✅
- 浮动输入框（/ 或 Cmd+K 唤起）✅
- 锁定机制 ✅
- Settings 面板（API Key、Provider、Model、Base URL）✅
- AI IO 日志 ✅

---

## 阶段 A：Agent 智能化（最优先）

> 目标：Agent 从"直接输出"变成"先规划、再确认、后执行"。
> 这是 TreeWorld 和普通聊天工具最核心的差异化，优先级最高。

### A1：两阶段工作流（Plan → Confirm → Execute）

**做什么：**
Agent 收到任务后不立即生成画布内容，而是先输出一份"画布规划"供用户确认。

规划包括：
- 任务理解：一句话复述用户意图
- 内容拆解：每个模块用什么块类型，理由是什么
- 结构预览：集合框的标题和子块列表

示例（用户输入"帮我学习 K 线"）：

```
我打算这样组织这个主题：

📋 集合框「K线基础」
├── MD 块：K线的来源与历史（文字说明适合 MD）
├── MD 块：K线的用途与场景
├── SVG 块：K线的构成（实体、上影线、下影线的图解）
├── HTML 块：K线形态互动展示（吞没形态、十字星、锤子线可点击查看）
└── MD 块：延伸阅读

确认后我开始生成，或者告诉我要调整什么。
```

用户回复"确认"或提出修改后，再执行 `canvas.batch` 生成实际内容。

**实现要点：**
- Agent 第一次调用 API 只生成 Plan JSON，不生成 canvas 指令
- 画布上出现一个"规划确认框"（特殊 UI，不是普通块）
- 用户点"确认"或在浮动输入框里回复后，发第二次 API 调用生成实际内容
- 支持用户说"把 SVG 块改成 MD 块"之类的修改，Agent 更新规划再确认

**Plan JSON 格式：**
```json
{
  "type": "plan",
  "summary": "帮你学习 K 线的基础知识",
  "collections": [
    {
      "title": "K线基础",
      "blocks": [
        { "type": "markdown", "title": "K线的来源与历史", "reason": "文字说明适合 MD 块" },
        { "type": "svg", "title": "K线的构成图解", "reason": "图形结构适合 SVG" },
        { "type": "html", "title": "K线形态互动展示", "reason": "可点击交互适合 HTML 块" }
      ]
    }
  ]
}
```

### A2：网页搜索能力

**做什么：**
Agent 执行任务时可以先搜索网页，基于真实信息生成画布内容。

**实现方式：**
- 接入 Tavily API（免费额度够用）或 Brave Search API
- 在 Settings 里加 Search API Key 配置
- 系统提示词里告诉 Agent 什么时候应该搜索（事实性问题、需要最新信息时）
- 搜索结果作为 context 塞进第二次 API 调用

**Agent 使用搜索的时机：**
- 用户问"最新的 XX 是什么"
- 用户要求"帮我调研 XX"
- 需要引用具体数据、价格、人名、事件时

**画布上的体现：**
- 搜索完成后，"思考中"状态显示"🔍 正在搜索..."
- 生成的 MD 块底部自动附上信息来源链接

---

### A3：SVG 块

**做什么：**
新增 SVG 块类型，Agent 可以生成矢量图形。

适合的内容：
- 结构图、流程图、架构图
- 数据图表（柱状图、折线图、饼图）
- 概念图解（如 K 线的构成）
- 思维导图

**实现要点：**
- SVG 内容直接用 `dangerouslySetInnerHTML` 渲染（SVG 不像 HTML 那么危险）
- 默认尺寸：宽 400px，高 300px
- Agent 生成的 SVG 要求：自包含（不引用外部资源）、有 viewBox、宽高用百分比

## 阶段 B：交互体验打磨

> 目标：让画布操作流畅，让块的使用不费力。

### B1：块的文字自适应缩放

**做什么：**
块的高度根据内容自动扩展，不依赖滚动条。

- MD 块：内容变多时，块高度自动增加（而不是出现滚动条）
- 便签块：同上
- 用户可以手动拖拽缩放（阶段一已有），自动扩展和手动缩放共存
- 手动设置过高度后，不再自动扩展（除非用户双击标题栏重置）

---

### B2：画布内浮动聊天框

**做什么：**
一个存在于画布世界坐标系内的聊天窗口，像其他块一样可以被拖动、可以被放在画布任意位置，但不是普通块——它是持久存在的对话入口。

外观：
- 圆角卡片，有轻微阴影，有标题栏"和 Agent 对话"
- 上半部分：对话历史列表（用户输入 + Agent 的 message 字段，时间倒序）
- 下半部分：输入框 + 发送按钮
- 默认尺寸：宽 340px，高 420px，可拖拽缩放
- 快捷键 `/` 或 `Cmd+K` 唤出（如果已在视口内则聚焦，否则 pan 到它并聚焦）

行为：
- 每条对话记录右侧有「→ 跳转」按钮，点击后画布 pan 到对应的集合框
- 聊天框本身可以被锁定（防止 Agent 移动它）
- 不参与 Agent 的画布内容生成，Agent 不会把它当成普通块操作

和现有浮动输入框的关系：
- 现有浮动输入框（快速唤出、用完即消失）保留，适合快速下指令
- 浮动聊天框适合需要看上下文、多轮对话的场景
- 两者共享同一个对话历史

### B3：实物化 UI 风格

**设计基调：**
参考两种参考物的设计语言——**纸框的有机残旧感**（层叠错位、触觉材质、暖黄褪色）和**CRT 电视的硬件分区感**（功能区域明确、机械密度、冷暖材质对话）。内容型块走前者，功能型块走后者。画布本身是软木板桌面，是容纳这一切的底层物理空间。

---

**MD 块 → 叠层纸页**

灵感来源：参考图2（纸框）的"层叠错位 + 触觉材质感 + 暖黄褪色色域"。

- 主体背景色 `#F5F0E8`（暖黄米色，模拟轻微氧化的纸）
- 块后方有 1-2 层错位叠影（用 `::before` / `::after` 伪元素实现），偏移 3-5px，颜色略深 `#E8E0CC`，模拟多页纸叠放
- 左侧边缘有细微的纸张厚度阴影（`box-shadow: -2px 0 4px rgba(0,0,0,0.08)`）
- 边缘轻微不规则感：用 `border-radius` 四角略不一致（如 `2px 3px 2px 4px`）
- 字体：衬线体（Lora，Google Fonts）
- 标题栏：无独立标题栏，标题直接作为正文第一行的 `# H1`，视觉上是纸页内容的一部分
- 锁定状态：左侧叠影变成红棕色，模拟"贴了封条"

---

**便签块 → 手撕便签**

- 背景色 `#FFF9C4`（便签黄），带 SVG 噪点纹理模拟纸面
- 顶部边缘用 CSS clip-path 做轻微锯齿，模拟手撕痕迹（不规则，非完美直线）
- 字体：手写体（Caveat，Google Fonts）
- 基于 `block.id` hash 计算固定旋转角度（-3° 到 +3°），每张便签旋转不同但刷新不变
- 投影方向随旋转角度偏移，保持物理一致性
- 无标题区，全部内容一视同仁

---

**图片块 → 拍立得照片**

- 白色厚边框：上/左/右边框 `12px`，底部边框 `40px`（拍立得特征留白）
- 底部白色区域可编辑标注文字，字体用 Caveat 手写体，默认文字浅灰色
- 顶部中央一枚图钉：用 CSS + SVG 绘制，圆形钉帽（深红色 `#8B3A3A`）+ 细针影
- 整体轻微旋转（同便签，基于 id hash，范围 -4° 到 +4°）
- 投影模拟照片悬浮在桌面上：`box-shadow: 3px 5px 12px rgba(0,0,0,0.25)`

---

**集合框 → 软木板钉区**

- 背景：CSS 模拟软木纹理（用 `repeating-conic-gradient` 或细点噪点，色值 `#C8A87A` 系）
- 边框：深棕实线 `#8B6914`，宽 3px，圆角 6px
- 标题：左上角一张小"标签纸"形状（梯形 clip-path），深棕底色白字，字体 Lora
- 子块之间有轻微投影，强化"都钉在同一块软木板上"的层次感
- 集合框本身无钉子，子块各自有钉（图片块有图钉，便签块的旋转暗示被钉住）

---

**SVG 块 → 制图纸 / 白板**

- 背景 `#FAFAFA`，四边有极细的网格线（模拟坐标纸，`#E8E8E8`，间距 20px）
- 边框：浅灰实线，圆角 4px
- 顶部标题栏：浅灰底色，左侧一个彩色细竖条（颜色由内容语义决定：图表蓝 `#4A90D9`、流程图绿 `#52B788`、架构图橙 `#E07A38`，Agent 生成时在指令里指定）
- 无机械感，保持"专业绘图工具"的克制风格

---

**HTML 块 → CRT 电视机 / 复古显示器**

灵感来源：参考图1（电视机）的"硬件面板层级 + 圆角矩形张力 + 冷暖材质对话 + 工业年代感氧化"。

- 外壳：暖米白色 `#F0EBE0`（模拟泛黄塑料外壳），圆角 8px，边框厚度 16-20px
- 屏幕区：内嵌深色边框（`#1A1A1A`，圆角比外壳大约 4px，产生"向心收拢感"），iframe 在此渲染
- 顶部控制栏：右侧有 2-3 个小圆形"旋钮"装饰（纯 CSS 圆形，深灰色，有光泽感），不可交互，纯视觉
- 底部有横向细栅格纹路（`repeating-linear-gradient`，模拟散热格栅）
- 整体投影偏重，模拟有厚度的实体设备
- 标题显示在外壳顶部，小号字，颜色 `#7A7060`（和外壳同色系，低调）

---

**浮动聊天框 → 桌面收音机 / 对讲机**

- 外壳暖灰色，有轻微圆角和厚度感
- 顶部天线装饰（细线 CSS 绘制）
- 对话气泡：用户的气泡偏米白，Agent 的气泡偏暖绿（模拟老式荧光屏文字色）
- 输入框区域有轻微栅格纹底（呼应电视机散热格栅）

---

**画布背景 → 软木桌面**

- 整体背景：低饱和度暖棕色，叠加细 SVG 噪点纹理，模拟软木桌面或旧木桌
- 网格点颜色调整为深棕（`#A0906A`），低对比度，不抢视觉焦点
- 支持在 Settings 里切换为：软木（默认）/ 深色皮革 / 浅色亚麻

---

**实现要点：**
- 所有材质效果只用 CSS + SVG 实现，不引入外部图片资源
- 旋转角度（便签、图片块）统一用 `hashAngle(block.id, min, max)` 工具函数计算，结果固定
- 叠层错位效果（MD 块）用 `::before` / `::after` 实现，不额外增加 DOM 节点
- HTML 块的 CRT 外壳是纯装饰层，iframe 内容不受影响
- 深色模式：纸张变 `#2A2520`，便签变 `#3D3820`，电视外壳变 `#2C2C2C`，整体降低实物感、保留轮廓

---

### B4：块操作菜单

**做什么：**
单击块的标题栏区域，弹出一个小操作菜单（不是右键菜单，不是 hover 工具条）。

菜单位置：标题栏正下方，左对齐弹出。

菜单内容：
- 🔒 锁定 / 解锁
- 📋 复制块
- 🗑️ 删除块
- ↗️ 在新窗口打开（HTML 块专用）
- 📌 置顶（z-index 提升）

行为细节：
- 单击标题栏 = 弹出菜单（不触发拖动）
- 拖动标题栏 = 拖动块（鼠标移动超过 4px 才算拖动，否则视为单击）
- 点击菜单外任意区域 = 关闭菜单
- 菜单打开时，该块 z-index 提升到最顶层

---

### B5：画布导航

**做什么：**
- 右下角小地图：显示所有块的位置缩略图，点击跳转
- `Cmd+0`：缩放到全局视图（所有块都可见）
- `Cmd+1`：缩放到 100%
- 搜索块：`Cmd+F` 弹出搜索框，搜索块标题和内容，点击跳转

## 阶段 C：更多块类型

> 目标：覆盖更多内容场景，让画布能承载更丰富的信息类型。

### C1：链接预览块

- 用户粘贴 URL，自动抓取 OG 信息（标题、描述、封面图）
- 显示为卡片样式：图片 + 标题 + 域名
- 点击跳转原链接

### C2：表格块

- Agent 可以生成 Markdown 表格，在表格块里渲染成真正的表格
- 支持点击单元格编辑
- 支持排序（点击列标题）

### C3：代码块

- 语法高亮（用 highlight.js 或 Shiki）
- 支持语言选择
- 一键复制
- 可选：在块内直接运行（仅 JavaScript，用 eval 沙箱）

### C4：Canvas 2D 块（低优先级）

- 适合实时数据可视化、粒子动画、游戏级交互
- 实现复杂，暂列为后续版本

## 阶段 D：系统能力

> 目标：让 TreeWorld 从"好玩"变成"可靠"。

### D1：初始页面 + 多画布管理

**做什么：**
应用启动时先进入初始页，管理多个画布，类似 Miro 的首页。

**初始页面：**
- 网格卡片布局，每个卡片代表一个画布
- 每张卡片显示：画布名称、最后编辑时间、画布内容缩略图（用 canvas 截图渲染）
- 右上角"新建画布"按钮
- 卡片 hover 时出现：打开、重命名、删除操作
- 支持画布搜索（按名称过滤）

**画布切换：**
- 点击卡片进入对应画布
- 画布内左上角有"← 返回首页"按钮
- 每个画布独立存储，互不干扰

**存储方案：**
- 数据存在 `localStorage`，key 结构为：
  ```
  treeworld:canvases         → 画布列表（id、name、updatedAt）
  treeworld:canvas:{id}      → 单个画布的完整 blocks + camera 状态
  ```
- 自动保存：每次操作后 debounce 800ms 写入
- 支持手动导出单个画布为 JSON 文件
- 支持从 JSON 文件导入画布（在初始页操作）

**初始页视觉风格：**
- 和画布实物化风格呼应：背景是浅木纹或软木板纹理
- 卡片像钉在软木板上的小画布缩略图
- 整体色调温暖，不是冷白的 SaaS 风格

### D2：撤销 / 重做

- `Cmd+Z` 撤销上一步操作（包括 Agent 的操作）
- `Cmd+Shift+Z` 重做
- 历史记录保留最近 50 步

### D3：本地模型接入

- Settings 里配置 Ollama Base URL
- 支持 Ollama 本地模型（llama3、mistral 等）
- 完全离线运行（数据不出本地）

### D4：桌面化（Electron 壳）

- Web 版功能稳定后，套 Electron 壳
- 桌面端支持：全局快捷键（不需要聚焦窗口）、系统托盘、开机启动

## 优先级总览

| 阶段 | 核心价值 | 建议时机 |
|---|---|---|
| A1 Plan→Confirm→Execute | TreeWorld 最大差异化 | 现在 |
| A2 网页搜索 | Agent 生成内容的质量 | A1 之后 |
| A3 SVG 块 | 覆盖图形化内容场景 | A1 之后 |
| B1 文字自适应 | 基础体验 | 和 A 并行 |
| B2 画布内浮动聊天框 | 对话历史可追溯 | B 阶段 |
| B3 实物化 UI 风格 | 产品气质和辨识度 | B 阶段 |
| B4 块操作菜单 | 操作效率 | B 阶段 |
| B5 画布导航 | 画布内容多了之后必需 | B 阶段 |
| C1-C3 更多块类型 | 内容覆盖度 | C 阶段 |
| D1 初始页面 + 多画布 | 可靠性 + 产品完整感 | 越早越好 |
| D2 撤销重做 | 容错能力 | D 阶段 |
| D3 本地模型 | 隐私用户 | D 阶段 |
| D4 桌面化 | 分发和体验 | 最后 |

---

## 一个建议

**D1 初始页面建议提前做，不等到 D 阶段。**

现在画布数据如果在 localStorage 里没有结构化存储，刷新页面就可能丢失。初始页面和多画布管理一起做，顺手解决持久化问题。在开始做 A1 之前，先让 Claude Code 把这个做好，之后所有功能都建立在"数据不会丢、可以管理多个画布"的基础上。
